# 웹 브라우저 게임 사이트 제작 완전 가이드 (2026년 기준)

> 웹 리서치 기반으로 정리한 실전 가이드. 기술 스택 선택 → 벤치마킹 → 게임 아이디어 → 필수 기능 → 무료 에셋 → 게임 주스(Juice)까지, 브라우저 게임 사이트를 만드는 데 필요한 모든 정보를 담았다.

## 1. 웹 게임 개발 기술 스택 (2026년 최신)

### 1.1 렌더링 API 지형도

| API | 상태 (2026) | 특징 |
|---|---|---|
| **HTML5 Canvas (2D)** | 모든 브라우저 100% 지원 | 가장 쉬움. 캐주얼/퍼즐 게임엔 이것으로 충분 |
| **WebGL / WebGL2** | 사실상 표준, 폴백(fallback)으로 여전히 중요 | GPU 가속 2D/3D. 대부분 엔진의 기본 렌더러 |
| **WebGPU** | Chrome 113+, Edge, Safari 26+ 지원. 글로벌 지원율 약 70~82%. Firefox만 기본 비활성 상태 | 차세대 API. 컴퓨트 셰이더 지원, WebGL 대비 큰 성능 향상. PixiJS v8, Three.js, Babylon.js가 이미 WebGPU 렌더러 제공 |

- 2025년 9월 Safari 26이 macOS/iOS/iPadOS에서 WebGPU를 지원하면서 마지막 큰 공백이 사라졌다. ([web.dev WebGPU 지원 발표](https://web.dev/blog/webgpu-supported-major-browsers))
- **실전 결론**: 2026년에도 "WebGPU 우선 + WebGL2 폴백" 구성이 안전하다. 단순 2D 게임이라면 순수 Canvas 2D로 시작해도 전혀 문제 없다.

### 1.2 주요 엔진/라이브러리 비교

|---|---|---|---|---|---|
| **바닐라 Canvas 2D** | API | 워들류, 2048, 퀴즈, 타이핑 | ★☆☆☆☆ | 의존성 0, 로딩 즉시 | 물리/씬 관리 직접 구현 |
| **[Phaser](https://phaser.io/)** (v4 안정화, 2026.4 "Caladan" 출시) | 풀 2D 엔진 | 플랫포머, 슈팅, 아케이드, 퍼즐 | ★★☆☆☆ | 물리(Arcade/Matter.js), 오디오, 입력, 씬, 타일맵, 파티클 등 올인원. 커뮤니티 최대 | 3D 불가, 번들 크기 큼 |

| **[KAPLAY](https://kaplayjs.com/)** (구 Kaboom.js) | 초보자용 2D 엔진 | 교육용, 잼(jam), 간단한 아케이드 | ★☆☆☆☆ | 의사코드 수준의 쉬운 문법, 웹 에디터(KAPLAYGROUND)와 90+ 예제. Kaboom.js는 폐기, KAPLAY가 커뮤니티 포크로 활발히 유지(v4000) | 대규모 게임엔 부적합 |
| **[PlayCanvas](https://playcanvas.com/)** | 3D 엔진+클라우드 에디터 | 3D 웹게임, 제품 시각화 | ★★★☆☆ | WebGPU 완전 지원(컴퓨트 셰이더 포함), 협업 에디터 | 에디터 종속성 |
| **Godot 4.x / Unity (웹 익스포트)** | 범용 엔진 | 본격 게임의 웹 이식 | ★★★☆☆ | 데스크톱급 툴체인. Unity 7은 WebGPU 기본 타깃 | 웹 번들이 무겁다(수십 MB), 로딩 느림 |

### 1.3 선택 가이드 (요약)

```
간단한 퍼즐/워들류/퀴즈  →  바닐라 JS + Canvas/DOM (엔진 불필요!)
2D 아케이드/플랫포머     →  Phaser 4 (또는 입문자는 KAPLAY)
고성능 2D 비주얼         →  PixiJS v8
3D                       →  Three.js(가볍게) / Babylon.js(본격적으로)
```

**핵심 인사이트**: 워들, 2048 같은 대박 게임은 전부 엔진 없이 순수 JS/CSS로 만들어졌다. 게임이 단순할수록 엔진을 걷어내라 — 로딩 속도가 곧 이탈률이다.

### 2.4 워들(Wordle)류 바이럴 게임의 교훈

워들은 2021년 11월 90명 → 2022년 1월 30만 명 → 1주 뒤 200만 명으로 폭발했다. ([Wikipedia](https://en.wikipedia.org/wiki/Wordle), [Smithsonian 분석](https://www.smithsonianmag.com/smart-news/heres-why-the-word-game-wordle-went-viral-180979439/))

바이럴 공식 4가지:

1. **이모지 공유 기능**: 🟩🟨⬛ 색 블록 결과 공유가 결정적이었다. 정답을 스포하지 않으면서 실력을 자랑/약올리는 구조 → 보는 사람이 궁금해서 클릭
2. **하루 1퍼즐 (인위적 희소성)**: 질리지 않고, 모두가 같은 문제를 푸는 "공동 경험" 생성
3. **극단적 단순함**: 설치 없음, 가입 없음, 설명 필요 없음. 3분이면 끝
4. **스트릭(연속 기록)**: 매일 돌아올 이유

> **사이트 설계 체크리스트**: 첫 클릭에서 플레이까지 3초 이내 / 가입 강요 금지 / 모바일 우선 / 결과 공유 버튼 필수 / 하루 단위 콘텐츠로 재방문 유도

## 4. 게임 사이트 필수 기능 구현

### 4.1 localStorage 저장 (점수·설정·스트릭)

```js
const save = (key, data) => localStorage.setItem(key, JSON.stringify(data));
const load = (key, fallback) => JSON.parse(localStorage.getItem(key)) ?? fallback;

// 예: 최고점수와 스트릭
const stats = load('gameStats', { best: 0, streak: 0, lastPlayed: null });
const today = new Date().toDateString();
if (stats.lastPlayed !== today) {
  const yesterday = new Date(Date.now() - 864e5).toDateString();
  stats.streak = (stats.lastPlayed === yesterday) ? stats.streak + 1 : 1;
  stats.lastPlayed = today;
  save('gameStats', stats);
}
```

### 4.2 SNS 결과 공유 (워들 스타일)

```js
async function shareResult(guesses, board) {
  const text = `내 게임 ${guesses}/6\n\n${board}\nhttps://mygame.example`;
  if (navigator.share) {              // 모바일: 네이티브 공유 시트
    await navigator.share({ text });
  } else {                            // 데스크톱: 클립보드 복사
    await navigator.clipboard.writeText(text);
    showToast('결과가 복사되었습니다!');
  }
}
// board 예: "🟩🟨⬛⬛⬛\n🟩🟩🟨⬛⬛\n🟩🟩🟩🟩🟩"
```

핵심: **정답을 스포하지 않는 시각적 결과물**을 만들 것. 이모지 그리드가 가장 검증된 형태.

### 4.3 리더보드 (랭킹)

| 방식 | 비용 | 적합 상황 |
|---|---|---|
| **[Supabase](https://supabase.com/)** (PostgreSQL) | 무료 티어 충분 | SQL 쿼리로 랭킹/기간별 집계가 쉬움. 2025년 이후 인디 개발자 선호도 1위 ([비교 분석](https://www.gorrion.io/blog/supabase-vs-firebase/)) |
| **Firebase Firestore** | 무료 티어 | 실시간 갱신 강점. [공식 리더보드 코드랩](https://firebase.google.com/codelabs/build-leaderboards-with-firestore) 있음 |
| **Redis ZSET** (Upstash 등) | 무료 티어 | 대규모 실시간 랭킹의 정석 |
| **전용 API** ([LEADR](https://www.leadr.gg/blog/free-open-source-leaderboard-api-for-games) 등) | 무료~ | 직접 백엔드 만들기 싫을 때 |

```sql
-- Supabase: 상위 10명 (RLS로 INSERT만 허용, UPDATE/DELETE 차단)
select nickname, score from scores
order by score desc limit 10;
```

**치트 방지 최소한의 수칙**: ① 클라이언트가 보낸 점수를 그대로 믿지 말 것 — 물리적으로 불가능한 점수(예: 플레이 시간 대비) 서버 측 검증 ② 점수 제출 API에 rate limit ③ 리플레이 데이터(입력 로그)를 함께 제출받아 검증하는 것이 정석. 완벽한 방지는 불가능하므로 "일일 리더보드 리셋"으로 피해를 한정하는 것도 효과적.

### 4.4 사운드 — [Howler.js](https://howlerjs.com/)

Web Audio API + HTML5 Audio 폴백을 한 번에 처리하고, 브라우저 자동재생(autoplay) 정책까지 관리해 준다.

```js
const sfx = new Howl({
  src: ['pop.webm', 'pop.mp3'],  // webm 우선, mp3 폴백
  sprite: { pop: [0, 300], win: [400, 1200] },  // 오디오 스프라이트
  volume: 0.7
});
sfx.play('pop');
```

- 모바일은 **첫 사용자 터치 이후**에만 소리 재생 가능 — 시작 버튼 클릭 시 오디오 컨텍스트를 unlock
- 전체 사운드 파일은 3~5MB 이하 유지 권장 ([모바일 최적화 가이드](https://dev.to/gamh5games/optimizing-html5-action-games-for-mobile-devices-19ce))
- 효과음 즉석 생성: [jsfxr](https://sfxr.me/) / [ZzFX](https://killedbyapixel.github.io/ZzFX/) (코드 한 줄짜리 초경량 효과음)

### 4.5 모바일 터치 대응

```js
canvas.addEventListener('touchstart', (e) => {
  e.preventDefault();  // 스크롤/줌 방지 — 필수!
  const t = e.touches[0];
  const rect = canvas.getBoundingClientRect();
  handleTap(t.clientX - rect.left, t.clientY - rect.top);
}, { passive: false });
```

```css
canvas { touch-action: none; }        /* 브라우저 제스처 차단 */
body { user-select: none; -webkit-tap-highlight-color: transparent; }
```

- `touchstart / touchmove / touchend` 3종 처리 ([MDN 터치 컨트롤 가이드](https://developer.mozilla.org/en-US/docs/Games/Techniques/Control_mechanisms/Mobile_touch))
- 또는 마우스+터치+펜을 통합하는 **Pointer Events** (`pointerdown` 등) 사용 권장
- 반응형 캔버스: 고정 해상도 대신 `devicePixelRatio` 반영 리사이즈

```js
function resizeCanvas() {
  const dpr = window.devicePixelRatio || 1;
  canvas.width  = canvas.clientWidth  * dpr;
  canvas.height = canvas.clientHeight * dpr;
  ctx.scale(dpr, dpr);   // 레티나에서도 선명하게
}
window.addEventListener('resize', resizeCanvas);
```

- `<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no">`
- 터치 타깃 최소 44×44px, 화면 하단(엄지 영역)에 주요 버튼 배치

### 4.6 기타 필수 요소

- **PWA**: manifest.json + 서비스 워커 → 홈 화면 추가, 오프라인 플레이
- **일시정지 처리**: `document.visibilitychange`에서 게임 루프/사운드 정지
- **게임 루프**: `requestAnimationFrame` + 델타타임 기반 업데이트 (프레임 독립적 이동)

## 6. 게임 주스(Juice) — 게임을 "맛있게" 만드는 기법

같은 게임도 주스가 있으면 완전히 다르게 느껴진다. 필견 자료: **"Juice it or Lose it"** (Martin Jonasson & Petri Purho, GDC) — 밋밋한 벽돌깨기에 파티클·화면 흔들림·사운드·트윈을 한 겹씩 얹어가며 변화를 보여준다. ([영상](https://www.youtube.com/watch?v=Fy0aCDmgnxg), [해설](https://gamejuice.co.uk/resources/juice-it-or-lose-it)) 함께 볼 것: [The Art of Screenshake (Vlambeer)](https://www.youtube.com/watch?v=AJdEqssNZ-U)

### 6.1 핵심 기법 목록

| 기법 | 효과 | 비용 |
|---|---|---|
| **화면 흔들림 (screen shake)** | 타격감·무게감. 0.1~0.3초면 충분, 과하면 멀미 | 코드 10줄 |
| **파티클** | 획득/파괴/착지의 시각적 보상 | 간단한 자작 시스템으로 충분 |
| **이징(easing) 트윈** | 선형 움직임 제거 → 모든 UI/오브젝트가 살아있는 느낌 | 함수 1줄 |
| **스쿼시 & 스트레치** | 점프/착지/충돌 시 찌그러뜨리기 → 물리적 존재감 | scale 트윈 |
| **히트스톱 (hit stop)** | 타격 순간 30~80ms 정지 → 임팩트 강조 | setTimeout 수준 |
| **숫자 카운트업** | 점수가 즉시 바뀌지 않고 촤르륵 올라감 | 보간 몇 줄 |
| **플래시 & 색 반전** | 피격 시 흰색 플래시 | 프레임 단위 오버레이 |
| **사운드 피치 랜덤화** | 같은 효과음도 `rate: 0.9~1.1` 랜덤 → 반복감 제거 | Howler 옵션 1개 |
| **콤보 이펙트 상승** | 연속 성공 시 이펙트·사운드 피치 점점 강화 | 상태 변수 1개 |

### 6.2 핵심 코드 패턴

```js
// 이징 함수 (라이브러리 없이) — https://easings.net 참고
const easeOutBack  = t => 1 + 2.7 * Math.pow(t - 1, 3) + 1.7 * Math.pow(t - 1, 2);
const easeOutElastic = t =>
  Math.pow(2, -10 * t) * Math.sin((t - 0.075) * (2 * Math.PI) / 0.3) + 1;

// 화면 흔들림 — 매 프레임 trauma 감쇠 방식
let trauma = 0;                       // 이벤트 발생 시 trauma = 0.5~1.0
function applyShake(ctx) {
  const shake = trauma * trauma;      // 제곱으로 부드러운 감쇠
  ctx.translate((Math.random() - 0.5) * 20 * shake,
                (Math.random() - 0.5) * 20 * shake);
  trauma = Math.max(0, trauma - 0.03);
}

// 미니 파티클
const particles = [];
function burst(x, y, color, n = 12) {
  for (let i = 0; i < n; i++) {
    const a = Math.random() * Math.PI * 2, s = 2 + Math.random() * 4;
    particles.push({ x, y, vx: Math.cos(a)*s, vy: Math.sin(a)*s, life: 1, color });
  }
}
function updateParticles(ctx, dt) {
  for (const p of particles) {
    p.x += p.vx; p.y += p.vy; p.vy += 0.15; p.life -= dt * 2;
    ctx.globalAlpha = Math.max(p.life, 0);
    ctx.fillStyle = p.color;
    ctx.fillRect(p.x, p.y, 4, 4);
  }
  ctx.globalAlpha = 1;
  particles.splice(0, particles.length,
    ...particles.filter(p => p.life > 0));
}
```

DOM 기반 게임(워들류)이라면 CSS만으로도 충분하다:

```css
.tile.pop  { animation: pop  .15s ease-out; }
.tile.flip { animation: flip .5s  ease forwards; }
.row.shake { animation: shake .4s; }           /* 오답 시 좌우 흔들림 */
@keyframes pop   { 50% { transform: scale(1.15); } }
@keyframes shake { 20%,60% { transform: translateX(-4px); }
                   40%,80% { transform: translateX(4px); } }
```

트윈 라이브러리가 필요하면: [GSAP](https://gsap.com/) (2024년부터 전면 무료), 이징 치트시트: https://easings.net

### 6.3 주스 적용 우선순위 (가성비 순)

1. 모든 상호작용에 **효과음** (+피치 랜덤) — 체감 효과 최대
2. 버튼/타일에 **호버·클릭 트윈**
3. 성공 순간 **파티클 + 카운트업**
4. 실패/충돌 순간 **흔들림 + 플래시**
5. 마지막에 배경음악과 앰비언트
